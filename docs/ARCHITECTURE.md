# ARCHITECTURE.md — мультисорс-ядро

## Задача

Пользователь ищет тайтл → ищем по всем сайтам → находим один и тот же тайтл
на нескольких → скачиваем с того, где перевод/выпуск актуальнее (глав больше).
Оттуда же показываем: чей перевод, сколько глав.

## Слои

```
        CLI / (в будущем) UI
                │
        ┌───────▼────────┐
        │   Aggregator   │  поиск по всем, группировка, выбор best
        └───────┬────────┘
                │ уточнение числа глав
        ┌───────▼────────┐
        │    Registry    │  id -> класс источника (switch между ядрами)
        └───────┬────────┘
     ┌──────────┼───────────┬───────────┐
 MangaLibSource ReMangaSource SenkuroSource …   ← подклассы MangaSource
     └──────────┴───────────┴───────────┘
                │  единый интерфейс
     search() / get_chapters() / get_pages()
```

## Единый контракт источника (`base.MangaSource`)

Три метода — всё, что нужно новому сайту:

```python
async def search(query, limit) -> list[SearchResult]
async def get_chapters(manga_id) -> list[ChapterInfo]
async def get_pages(manga_id, chapter) -> list[PageInfo]   # абсолютные URL
```

Общее в базовом классе: httpx-клиент с ретраями (`request_with_retries`),
подстановка `Authorization: Bearer` из токена, `_get_json`/`_get_text`.

DTO (все `@dataclass`):
- `SearchResult` — тайтл на сайте (id, названия, обложка, url, число глав).
- `ChapterInfo` — глава (том/номер/имя/команда/ветка).
- `PageInfo` — страница (index, абсолютный url, заголовки напр. Referer).

## Переключение между ядрами (`registry.py`)

`_ALL` — список классов в порядке приоритета. `create_source(id, token)`
создаёт экземпляр. Добавить сайт = написать адаптер + одна строка в `_ALL`.
Заглушки (`stubs.py`) видны в реестре, но методы поднимают `SourceError` —
список сайтов честно отражает ТЗ.

## Выбор «самого актуального» (`aggregator.py`)

1. `search_all(query)` — параллельно (`asyncio.gather`) опрашивает источники;
   сбой одного не роняет остальные (ошибки собираются в `on_error`).
2. `_group()` — склеивает результаты одного тайтла по совпадению любого из
   нормализованных названий (латиница+кириллица, без пунктуации/регистра).
3. `enrich_counts(title)` — где поиск не отдал число глав, тянет `get_chapters`
   и считает **уникальные** главы по `(volume, number)` — чтобы сайт с тремя
   ветками перевода не выглядел «полнее» реального.
4. `AggregatedTitle.best` — источник с максимумом глав. Его и качаем.

Компромисс сопоставления названий: favors recall (лучше склеить лишнее, чем
разорвать тайтл). Если начнёт склеивать разные тайтлы — порог похожести
(rapidfuzz). Помечено `ponytail:`-комментарием в коде.

## Скачивание (`download.py`)

Отдельно от `downloader.py` (тот заточен под CDN MangaLib с относительными
путями и списком серверов). Мультисорс-страницы — уже готовые абсолютные URL
с заголовками, поэтому свой компактный загрузчик поверх общих ретраев и
определения формата (`_detect_ext`).

## Токены (`token_window.py`, `token_store.py`)

Dev-инструмент: QtWebEngine с постоянным профилем. Перехватчик запросов ловит
`Authorization: Bearer …`, который сайт шлёт своему API; запасной путь — разбор
`localStorage` (там `eyJ…`-JWT). Сохранение в `tokens.json` (конфиг-папка).
Агрегатор по умолчанию подхватывает сохранённые токены.

## Как добавить новый сайт

1. `sources/<site>.py`: подкласс `MangaSource`, реализовать три метода.
2. Зарегистрировать в `registry._ALL` (убрать соответствующую заглушку).
3. Тест парсера на зафиксированном ответе в `tests/test_parsers.py`.
4. При необходимости логина — добавить URL в `token_window.LOGIN_URLS`.
