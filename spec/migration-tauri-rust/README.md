# Спека: миграция на Tauri + Rust

Пакет документов для перехода `mangalib-manga-downloader` с Python/PySide6 на
**Tauri 2 (фронт) + Rust (ядро)**, цели сборки — **Windows + Android**. Собран
через spec-pilot (интервью → спека → делегирование → проверка) и graphify (граф
текущей кодовой базы).

> **Статус: ЧЕРНОВИК НА УТВЕРЖДЕНИЕ.** Это только спека. Код не переписывается,
> пока ты не скажешь «спека ок, начинаем». Порядок spec-pilot: сборку не
> начинаем без явного «да» (Гард 2).

## Зафиксированные решения (2026-07-18)

- **Фронт:** Svelte 5 + TypeScript + Vite (один на desktop и Android).
- **Платформы v1:** Windows + Android (iOS отложен).
- **Токены:** один путь — встроенный webview + чтение `localStorage` через JS
  (проще и работает на обеих платформах).
- **Python-версия** остаётся эталоном до закрытия паритета, потом архивируется.

Детали и обоснование — в [PRD.md §7](PRD.md), мобильные особенности —
[ARCHITECTURE.md §11](ARCHITECTURE.md).

## Ключевые вводные (из графа кодовой базы)

graphify-анализ выделил **god-nodes** — самые связные абстракции, которые
миграция обязана сохранить наиболее бережно (это несущий контракт):

1. `ChapterInfo` (58 связей), `MangaSource` (51), `SearchResult` (48),
   `PageInfo` (43) — **мультисорс-контракт**. В Rust это трейт + DTO-структуры.
2. `MangaLibClient` (38), `RateLimiter` (24), `DownloadService` (20) — движок.
3. `MainWindow`, `CatalogDialog` — GUI на PySide6 → **переписывается** на Tauri-фронт
   (порт не нужен, UI трогать по ТЗ можно только в рамках миграции).

Сообщества графа дали естественные единицы миграции — см.
[MIGRATION-PLAN.md](MIGRATION-PLAN.md), раздел «Порядок по сообществам».

## Главное требование заказчика по тестированию

Нужны **кастомные инструменты тестирования**: в частности — тестировать скачку с
**каждого сайта по отдельности** через переключатель/особый режим запуска
приложения, плюс другие варианты тестирования. Полностью раскрыто в
[TESTING.md](TESTING.md).
